    Configuration Reference¶

    This page is auto-generated from the Pydantic models in config.py. All configuration is validated with extra="forbid" — any unknown fields will raise an error.

    WorkflowConfig¶

    Top-level workflow configuration. This is the root object for all seekr-chain configs.

    Field Type Default Description
    name str required Workflow name (must be DNS-compliant)
    namespace str, optional argo Kubernetes namespace for the Argo workflow
    code CodeConfig, optional None Local code directory to upload into job containers
    ttl duration 7d Time-to-live after completion before automatic cleanup
    artifact_ttl duration 90d Time-to-live for S3 job artifacts (code package, logs, data) before background cleanup deletes them
    steps list[SingleRoleStepConfig | MultiRoleStepConfig] required List of workflow steps
    secrets dict[str, str | EnvSource | SecretRefSource], optional None Secrets injected as environment variables in each step
    env dict[str, str], optional None Global environment variables for all steps
    affinity list[Annotated], optional None Scheduling rules — list of node and pod affinity/anti-affinity rules
    scheduling SchedulingConfig, optional None Queue and priority for job admission (e.g. Kueue LocalQueue)
    logging LoggingConfig (see below) Log collection settings
    labels dict[str, str], optional None
    controller_image str, optional None

    CodeConfig¶

    Local code directory to upload into job containers. When specified, S3 credentials are automatically injected.

    Field Type Default Description
    path str required Local directory to upload
    exclude list[str], optional ['.venv', '.git', '__pycache__', '.pytest_cache', '.ruff_cache', '*.pyc'] Glob patterns to exclude from upload. The default drops virtualenvs, the git dir, and the Python/test/lint caches that otherwise bloat the upload and (for nix-mode) churn the flake closure between runs. Set exclude: [] or add an include to ship any of these.
    include list[str], optional None Glob patterns to include (default: everything)

    NixConfig¶

    Use a nix closure as the runtime instead of a Docker image. The role's container runs a minimal "nix-runner" OCI image that holds nix + s5cmd. At pod startup it pulls the closure from the configured binary cache into /nix/store and runs the user script with the closure's bin/ on PATH. Image distribution shifts from docker pull (sequential layer extract) to nix copy --from (per-path parallel fetches with cross-image deduplication). At submit time seekr-chain evaluates <expression>#<attr>.outPath locally (requires nix on the submit machine) to compute the content-addressed closure path. If the closure is missing from the store and build=True (default), seekr-chain injects a build step into the DAG that runs nix build + nix copy --to against the store.

    Field Type Default Description
    expression str ./ Path to a flake directory or .nix file, relative to code.path. Same string is used at submit time (for eval) and inside the build pod (for nix build).
    attr str default Attribute path within the expression to materialize (default: "default").
    system str x86_64-linux Target system for the closure (default: "x86_64-linux").
    store str, optional None URI for the binary cache (e.g. s3://bucket). Any nix store type works; see https://nix.dev/manual/nix/2.26/store/types/. Defaults to ~/.seekrchain.toml's nix_store.
    build bool True Whether to auto-build a missing closure by injecting a build step into the DAG. Set False to fail at submit time if the closure isn't already in the store — useful to enforce "must be pre-built" semantics for some workflows.
    build_resources ResourceConfig, optional None Resources for the auto-injected build step. Defaults are modest (4 CPU / 16 GiB RAM / 0 GPU) — fine for small python closures; large native builds (pytorch from source, flash-attn) want much more and should set this explicitly.
    build_max_jobs int | Literal['AUTO'] 1 Maximum number of derivations Nix may build concurrently. Accepts a non-negative integer or "AUTO" (case-insensitive). Defaults to Nix's standard value of 1.
    build_cores int 0 Number of build cores Nix exposes to each derivation. Zero means all available cores. Defaults to Nix's standard value of 0.
    include list[str], optional None Optional list of root-relative glob patterns that define the source tree staged for nix eval/build. Unset (the default): nix shares code's filtered tree exactly, no separate copy, no duplicate upload. Set: this replaces code.include for nix (not ANDed with it) — a role can point nix.include at a completely different subtree than code.include and still get real content there. Use this to keep flake invalidation narrow in a large repo where code.include is broad; the tradeoff is a separate materialized copy, so any files also covered by code.include are uploaded twice. In practice that's cheap: nix.include is meant to be a small curated set (flake.nix, lockfiles, ...), and it's only staged/uploaded for closures that still need building, not on every submit.
    exclude list[str], optional None Optional list of root-relative glob patterns excluded from the nix source tree. Applied after include. Same replace-not-AND relationship with code.exclude as above.
    ResourceConfig¶

    Compute resource requests for a step.

    Field Type Default Description

    DependsOnCondition¶

    A conditional dependency edge — gates a step on another step's outcome. Reuses FailureRule's on_exit_codes/operator shape so users only need to learn one exit-code-gating vocabulary.

    Field Type Default Description
    step str required Name of the step this condition depends on.
    when Literal['ON_SUCCESS', 'ON_FAILURE', 'ALWAYS'] ON_SUCCESS ON_SUCCESS (default) requires step to succeed. ON_FAILURE requires step to fail (or be cancelled). ALWAYS is satisfied once step reaches any terminal state, regardless of outcome.
    on_exit_codes list[int], optional None Exit codes to match against, gating ON_FAILURE further. Optional; None means any failure matches. Requires when == ON_FAILURE.
    operator Literal['IN', 'NOT_IN'] IN Whether on_exit_codes is an inclusion or exclusion list.

    Field Type Default Description
    max_restarts int, optional 0 Maximum number of restarts before failing
    rules list[FailureRule] [] Failure handling rules
    FailureRule¶

    A rule for handling failures.

    Field Type Default Description
    action Literal['FAIL_JOB_SET', 'RESTART_JOB_SET', 'RESTART_JOB_SET_AND_IGNORE_MAX_RESTARTS'] RESTART_JOB_SET Action to take on failure
    target_roles list[str], optional None Roles this rule applies to (multi-role steps only)
    on_exit_codes list[int], optional None Container exit codes this rule matches. Optional; None means the rule matches all failures unconditionally (today's behavior). When set, action must be FAIL_JOB_SET.
    operator Literal['IN', 'NOT_IN'] IN Whether on_exit_codes is an inclusion or exclusion list

    EnvSource¶

    Read the secret value from the local environment at submit time. The resolved value is stored transiently in the per-job secret store entry and injected as an environment variable in each container.

    Field Type Default Description
    env str | bool required Name of the local environment variable to read, or True to use the same name as the secrets dict key.

    SecretRefSource¶

    Reference a secret that already exists in the backend secret store. The value is never read, copied, or logged by seekr-chain — the container runtime resolves it directly from the named secret store entry.

    Field Type Default Description
    secretRef SecretRef required Pointer to the secret store object and key.

    SecretRef¶

    Pointer to a key within a backend secret store (e.g. a Kubernetes Secret).

    Field Type Default Description
    name str required Name of the secret store object (e.g. the Kubernetes Secret name).
    key str, optional None Key within the secret store object. Defaults to the secrets dict key (i.e. the injected environment variable name) when omitted.

    NodeAffinityRule¶

    Schedule based on node properties (hostname or labels).

    Field Type Default Description
    type Literal['NODE'] required Discriminator — always "NODE".
    direction Literal['ATTRACT', 'REPEL'] ATTRACT "ATTRACT" schedules on matching nodes; "REPEL" avoids them.
    hostnames list[str], optional None Match against kubernetes.io/hostname.
    labels dict[str, list[str]], optional None Match against arbitrary node labels (key → allowed values).
    required bool True True (default) = hard constraint; False = soft preference.

    PodAffinityRule¶

    Schedule based on where other pods in a named group are running.

    Field Type Default Description
    type Literal['POD'] required Discriminator — always "POD".
    direction Literal['ATTRACT', 'REPEL'] ATTRACT "ATTRACT" co-locates with the group; "REPEL" avoids nodes where the group is running.
    group str required Shared identifier. All jobs submitted with the same group value carry the label seekr-chain/pg.<group>: "true" on their pods.
    required bool False False (default) = soft preference; True = hard constraint. .. warning:: direction="ATTRACT" with required=True will deadlock on a fresh submission — no nodes satisfy the constraint until at least one pod from the group is already running. Use required=False (the default) unless you are adding jobs to an already-running group.

    SchedulingConfig¶

    Scheduling configuration for job queue admission. Maps to backend-specific queue primitives (e.g. Kueue LocalQueue on Kubernetes, partition on SLURM).

    Field Type Default Description
    queue str required Queue or partition name to submit this workflow's jobs to
    priority str, optional None Optional priority class / QOS name

    LoggingConfig¶

    Log collection settings.

    Field Type Default Description
    upload_timeout duration 1m Timeout for uploading logs to S3

    StepConfig¶

    Each entry in steps is either a SingleRoleStepConfig (most common — a single container job) or a MultiRoleStepConfig (multiple roles running in parallel, e.g. server + workers). seekr-chain auto-detects which type based on whether the roles field is present.
